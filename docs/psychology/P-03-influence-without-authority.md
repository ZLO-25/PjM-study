# P-03 沒有職權的影響力 (Influence without Authority)

**沒有職權時，影響力來自交換：你先理解對方在乎什麼，再提供對方重視的東西，換取專案需要的配合；關係是長期累積的帳戶，不是一次性的交易。**

```text
 影響力的交換循環

 1. 把對方當潛在盟友
        │
        ▼
 2. 釐清自己要什麼（具體）
        │
        ▼
 3. 了解對方在乎什麼
        │
        ▼
 4. 找出自己能給的「貨幣」
        │
        ▼
 5. 交換，並維護關係
        │
        └──► 下一次合作更容易

 常見的「貨幣」
 ┌─ 資訊：提早讓他知道會影響他的事
 ├─ 協助：幫他解決一個小問題
 ├─ 認可：在他的主管面前肯定他
 ├─ 參與：讓他參與決定
 └─ 資源：分享工具、範本、人力
```

=== "入門"

    **白話解釋**

    上面的循環參考了組織行為學中常被引用的「影響力交換」觀點（Cohen 與 Bradford 的研究常被提到）。核心概念：在組織中，人們用各種「貨幣」互相交換，即使沒有上下關係，也能建立合作。

    幾個常用的影響力原則：

    - **互惠**：先給，對方比較願意回報。
    - **一致性**：人傾向做和自己說過的話一致的事。請對方在會議上表態支持，後續比較會配合。
    - **社會認同**：「其他兩個廠區已經完成」比「請你配合」更有說服力。
    - **權威**：引用專業標準或可信的資料，而不是「長官要的」。

    **IT 例子**

    你需要應用團隊配合做連線測試。直接要求：「請在週五前完成測試。」交換式說法：「我們可以幫你們先在測試環境跑一次，把常見問題列給你們，這樣你們的測試應該可以縮短一半。週五前可以安排嗎？」

    **最常見的誤解**

    「影響力 = 操弄。」操弄是隱藏意圖、讓對方做違背自己利益的事。真正的影響力是公開的交換，雙方都得到好處。如果對方事後覺得被騙，你只會失去影響力。

=== "進階"

    **取捨與兩難**

    - 關係帳戶要在**不需要的時候**存款。等到要人幫忙才去經營關係，對方會覺得你只在有需要時才出現。
    - 過度依賴交換，會讓每件事都變成談條件。資深 PM 會讓一部分的合作建立在「共同目標」上，而不只是互惠。

    **跨主題的互動**

    - 影響力的基礎是權力來源，見 [T-03 PM 的角色與權力來源](../theory/T-03-pm-role-and-power.md)。
    - 矩陣式組織中這是必要技能，見 [T-20 矩陣式組織](../theory/T-20-matrix-organization.md)。
    - 對上級的影響力見 [P-05 向上管理](P-05-managing-up.md)。

    **資深 PM 怎麼判斷**

    資深 PM 在請求別人之前，會先回答一個問題：「如果我是他，我為什麼要答應？」答不出來，就先去了解對方，而不是急著開口。

## 明天上班可以怎麼用

- 挑一位你常需要但不歸你管的人，列出三種你能提供給他的「貨幣」。
- 這週主動給一次資訊或協助，不要求任何回報。
- 下次請求別人時，先說「這對你們的好處是……」，再說你需要什麼。

## 小測驗

你需要另一個部門的資深工程師幫忙審查設計，但他很忙，過去兩次都說沒空。以下哪個做法最符合「影響力交換」？

- A. 請你的主管跟他的主管說
- B. 了解他目前最頭痛的問題，例如他正在準備一份技術報告，你可以提供你專案的實測數據給他使用，同時請他撥 30 分鐘審查重點部分
- C. 寄一封正式信件，副本給所有相關主管
- D. 放棄，找別人審查

??? success "看答案與解析"
    **答案是 B。**

    - **A 錯：** 越級可能有效，但會讓這位工程師覺得被逼，審查品質不一定好，下次更難合作。
    - **B 對：** 找出對方在乎的東西（技術報告需要數據），提供有價值的貨幣，並把請求縮小到合理的範圍（30 分鐘、重點部分）。
    - **C 錯：** 大量副本是施壓，不是影響。
    - **D 錯：** 如果他是最適合的審查者，放棄會影響設計品質。換人是選項，但不該是第一步。
