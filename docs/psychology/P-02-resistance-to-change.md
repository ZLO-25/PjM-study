# P-02 變革抗拒 (Resistance to Change)

**人抗拒的通常不是改變本身，而是改變帶來的損失：熟悉的做法、能力上的優勢、可預期的工作、或在組織中的位置；處理抗拒，要先承認這些損失是真的。**

```text
 面對改變時常見的情緒曲線

 士氣
  高 │──╮                         ╭────
     │   ╲  否認                 ╱ 接受與投入
     │    ╲                    ╱
     │     ╲  抗拒           ╱ 嘗試
     │      ╲              ╱
  低 │       ╰──── 低谷 ──╯
     └──────────────────────────────────► 時間
         宣布改變          新做法上手

 PM 的工作：縮短低谷、讓人更快走到嘗試
```

=== "入門"

    **白話解釋**

    常見的抗拒原因：

    - **失去能力感**：在舊系統上是專家，在新系統上變成新手。
    - **失去控制**：改變是別人決定的，自己沒被問過。
    - **不確定**：不知道改變後自己的工作會變成怎樣。
    - **額外負擔**：學新東西的時間沒有被扣掉原本的工作量。
    - **過去的經驗**：上一次改變很痛苦，或者承諾沒有兌現。

    （上圖的情緒曲線常被拿來說明個人面對改變的歷程，源自對哀傷歷程的研究，被廣泛借用到組織變革。它是一種幫助理解的模型，不是每個人都會照順序經歷。）

    **IT 例子**

    新的網路設定自動化平台上線，資深工程師最抗拒。因為他手打指令比誰都快，平台讓他的專長變得不重要。處理方式：邀請他參與設計自動化範本，讓他的專長轉化成平台的一部分。

    **最常見的誤解**

    「抗拒的人就是不配合。」抗拒常常是有價值的訊號：它告訴你改變的設計哪裡沒考慮到使用者，或者溝通哪裡出了問題。

=== "進階"

    **取捨與兩難**

    - 讓每個人都參與決策會讓改變變慢；但沒有參與的改變，執行時阻力更大。常見的平衡是讓代表參與設計，並讓所有人在試行期提供回饋。
    - 有些損失無法彌補（例如某個職務真的會消失）。這時誠實比安撫更重要，因為人們遲早會發現真相。

    **跨主題的互動**

    - 參與度的規劃見 [T-07 利害關係人參與規劃](../theory/T-07-stakeholder-engagement.md)。
    - 抗拒背後的恐懼見 [P-01 利害關係人的動機與恐懼](P-01-stakeholder-motives.md)。
    - 移交時維運團隊的抗拒見 [T-28 結案與移交](../theory/T-28-closure-handover.md)。

    **資深 PM 怎麼判斷**

    資深 PM 會區分兩種抗拒：「對內容的抗拒」（方案真的有問題）和「對過程的抗拒」（方案沒問題，但人沒被尊重）。前者要改方案，後者要改做法。混在一起處理，兩者都解決不了。

## 明天上班可以怎麼用

- 對你專案影響最大的使用者群體，寫下「這個改變會讓他們失去什麼」。
- 找一位最有影響力的抗拒者，邀請他參與一個具體的設計決策。
- 規劃改變時，把「學習新做法的時間」排進對方的工作量裡。

## 小測驗

新的工單系統上線一個月，資深工程師仍然私下用舊方式處理工作。最可能有效的做法是？

- A. 發公告規定所有人必須使用新系統，違者記點
- B. 和這幾位工程師個別聊，了解新系統讓他們做不到或變慢的地方，把可以改的列入改善，並請他們協助設計改善方案
- C. 關掉舊方式，讓他們沒有選擇
- D. 放任不管，時間久了自然會習慣

??? success "看答案與解析"
    **答案是 B。**

    - **A 錯：** 強制可能換來表面使用，但抗拒的原因沒有解決，資料品質可能更差。
    - **B 對：** 把抗拒當成回饋，同時讓資深者參與改善，處理了「能力感」與「控制感」的損失。
    - **C 錯（不一定錯）：** 最終可能需要關掉舊方式，但在了解原因之前就關掉，可能讓工作真的做不下去。
    - **D 錯：** 兩套並行會讓資料分散，抗拒也可能擴散到其他人。
