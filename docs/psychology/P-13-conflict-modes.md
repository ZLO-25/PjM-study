# P-13 衝突處理模式 (Conflict Handling Modes)

**處理衝突有五種基本模式，差別在於你多在乎「達成自己的目標」以及多在乎「維護對方的目標」；沒有一種模式永遠最好，重點是依情境選擇。**

```text
 Thomas-Kilmann 衝突模式

 堅持己見
 （在乎自己的目標）
  高 │  競爭               合作
     │  Competing          Collaborating
     │
     │          妥協
     │          Compromising
     │
  低 │  迴避               遷就
     │  Avoiding           Accommodating
     └────────────────────────────────────►
        低                              高
                 配合他人（在乎對方的目標）
```

=== "入門"

    **白話解釋**

    這個模型由 Kenneth Thomas 與 Ralph Kilmann 提出，常被稱為 TKI。

    | 模式 | 意思 | 適合的時候 | 用錯的代價 |
    |---|---|---|---|
    | 競爭 | 堅持自己的立場 | 緊急、安全問題、原則問題 | 傷關係 |
    | 合作 | 一起找雙贏方案 | 問題重要、有時間、關係重要 | 耗時 |
    | 妥協 | 各退一步 | 時間有限、雙方力量相當 | 兩邊都不完全滿意 |
    | 遷就 | 讓對方的目標優先 | 對自己不重要、想累積關係 | 一直遷就會被看輕 |
    | 迴避 | 暫時不處理 | 情緒太高、問題不重要 | 問題會累積 |

    **IT 例子**

    - 割接中發現可能影響生產系統的風險 → **競爭**：PM 立刻要求暫停，不需要協商。
    - 兩個團隊對架構設計有不同意見 → **合作**：找出雙方的顧慮，設計一個都能接受的方案。
    - 會議室時段衝突 → **遷就**：讓給對方，累積關係。
    - 會議上兩人情緒激動 → **迴避**（暫時）：「我們先休息十分鐘，會後再討論。」

    **最常見的誤解**

    「合作永遠是最好的。」合作需要時間和雙方的意願。凌晨三點割接出問題時，PM 需要的是果斷決定，不是開一個雙贏工作坊。

=== "進階"

    **取捨與兩難**

    - 每個人都有習慣的模式。技術背景的人常習慣「競爭」（我的方案技術上比較好）或「迴避」（不想處理人的問題）。知道自己的傾向，才能有意識地切換。
    - 衝突有兩種：**任務衝突**（對事情的不同看法）通常有益，能帶來更好的方案；**關係衝突**（對人的不滿）通常有害。PM 的工作是讓衝突留在任務層次。

    **跨主題的互動**

    - 矩陣式組織中的雙重報告是衝突常見來源，見 [T-20 矩陣式組織](../theory/T-20-matrix-organization.md)。
    - 合作模式的實作方法見 [P-04 原則式談判與 BATNA](P-04-principled-negotiation.md)。
    - 風暴期的衝突見 [P-12 團隊發展階段](P-12-team-development-stages.md)。

    **資深 PM 怎麼判斷**

    資深 PM 面對衝突時會先問兩個問題：「這件事有多重要？」和「這段關係有多重要？」兩者都重要 → 合作；事情重要、時間緊 → 競爭；關係重要、事情不重要 → 遷就。

## 明天上班可以怎麼用

- 回想最近一次衝突，你用的是哪一種模式？如果重來，會選哪一種？
- 下次衝突時，先說出對方的立場：「我理解你擔心的是……」，再說自己的。
- 發現衝突從「事」轉到「人」時，暫停並把焦點拉回事情本身。

## 小測驗

網路團隊和資安團隊對防火牆架構意見不同：網路團隊重視效能，資安團隊重視隔離。專案還有三週才需要定案。最適合的處理模式是？

- A. 競爭：PM 直接選一個方案
- B. 合作：請雙方說明各自的顧慮與需求，一起設計同時滿足效能與隔離要求的方案
- C. 迴避：等到最後一週再處理
- D. 遷就：讓資安團隊決定，因為資安比較重要

??? success "看答案與解析"
    **答案是 B。**

    - **A 錯：** 有三週時間，問題重要，雙方的專業都有價值，直接裁決會浪費雙方的知識，也會讓一方不滿。
    - **B 對：** 事情重要、關係重要、時間足夠，正是合作模式最適合的情境。
    - **C 錯：** 拖到最後只會讓時間壓力逼出一個倉促的決定。
    - **D 錯：** 遷就在這裡會犧牲效能需求，而且網路團隊會覺得自己的專業不被重視。
