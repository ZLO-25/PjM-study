# P-11 心理安全感 (Psychological Safety)

**心理安全感是團隊成員共同相信「在這裡說出問題、承認錯誤、提出不同意見，不會被羞辱或懲罰」；它決定了壞消息能不能及早浮上來。**

```text
 心理安全感 × 標準要求（四種團隊狀態）

 標準要求
  高 │  焦慮區          │  學習區
     │  怕犯錯、隱藏問題 │  敢說、也追求好
     ├──────────────────┼──────────────────
  低 │  冷漠區          │  舒適區
     │  沒人在乎         │  開心但不進步
     └──────────────────┴──────────────────► 心理安全感
           低                    高

 目標：學習區
 心理安全感 ≠ 降低標準
```

=== "入門"

    **白話解釋**

    「團隊心理安全感」這個概念由哈佛商學院的 Amy Edmondson 系統化研究。Google 內部的團隊效能研究（常被稱為 Project Aristotle）也將它列為高效團隊最重要的因素之一。

    心理安全感**不是**：

    - 大家都很客氣、不吵架。
    - 降低要求、做錯沒關係。
    - 每個人都要同意。

    心理安全感**是**：

    - 新人敢問「這個我不懂」。
    - 工程師敢說「我覺得這個割接計畫有問題」。
    - 有人犯錯時，大家討論的是「怎麼避免再發生」，而不是「誰的錯」。

    **IT 例子**

    割接前一天，一位年輕工程師發現回退腳本有一步沒測過，但他想「資深的人應該都看過了」，就沒說。割接時回退失敗。這不是他個人的問題，而是團隊缺乏讓他敢開口的環境。

    **最常見的誤解**

    「心理安全感就是對人好。」心理安全感和高標準可以共存，而且最好的團隊兩者都高：對事要求嚴格，對人尊重。

=== "進階"

    **取捨與兩難**

    - 建立心理安全感需要時間，破壞它只需要一次。一次公開責罵，可能讓整個團隊在接下來幾個月都不敢說真話。
    - PM 不一定是團隊成員的主管，但 PM 主持會議、主導復盤，對團隊氛圍的影響很大。

    **跨主題的互動**

    - 沒有心理安全感，壞消息就會延遲上報，見 [P-15 壞消息上報延遲](P-15-mum-effect.md)。
    - 復盤是否有效，取決於心理安全感，見 [T-29 經驗回顧與復盤](../theory/T-29-lessons-learned.md)。
    - 敏捷的回顧會議也是如此，見 [T-25 敏捷價值與 Scrum](../theory/T-25-agile-scrum.md)。

    **資深 PM 怎麼判斷**

    資深 PM 觀察心理安全感的方法很簡單：會議上誰在說話？如果永遠只有資深的人和主管在說話，新人從來不提問，那心理安全感可能不夠。

## 明天上班可以怎麼用

- 在下次會議上，先示範脆弱：「這部分我不確定，誰比較清楚？」
- 當有人提出問題或壞消息時，第一句話說「謝謝你說出來」。
- 割接或重要決策前，專門問一次：「有沒有人覺得哪裡怪怪的？任何小事都可以說。」
- 主持復盤時遵守對事不對人，方法見 [W-18 主持復盤會議](../practice/W-18-retrospective.md)。

## 小測驗

在割接前的最後檢查會議上，一位資淺工程師小聲說：「我覺得第 8 步的順序好像有問題……不過應該沒關係。」最適合的回應是？

- A. 「如果你不確定，就不用說了。」
- B. 「謝謝你提出來，這很重要。我們現在一起看看第 8 步，你覺得哪裡有問題？」
- C. 「這份計畫資深的人都審過了，應該沒問題。」
- D. 會後再私下問他

??? success "看答案與解析"
    **答案是 B。**

    - **A 錯：** 等於告訴他「不確定就別說話」，以後他就真的不說了。
    - **B 對：** 先肯定行為（提出問題），再立刻處理內容。這同時保護了割接的品質和團隊的心理安全感。
    - **C 錯：** 用資歷否定問題，傳達的訊息是「資淺的人的意見不重要」。
    - **D 錯：** 割接前的問題要立刻處理；會後再問可能已經來不及，也錯過了讓全隊看到「提出問題是被歡迎的」的機會。
