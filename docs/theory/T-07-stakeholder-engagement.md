# T-07 利害關係人參與規劃 (Stakeholder Engagement)

**參與規劃是把每個關鍵利害關係人「現在的態度」和「專案需要的態度」對照出來，再設計具體行動縮小落差。**

```text
 參與度評估矩陣（C = 現在，D = 需要）

 利害關係人   不知情  抗拒   中立   支持   主導
 ──────────   ──────  ────   ────   ────   ────
 業務主管                    C ───► D
 維運主管            C ─────────► D
 資安單位     C ──────────► D
 發起人                             C      D

 落差越大，越需要提早投入時間
```

=== "入門"

    **白話解釋**

    參與度通常分五級：**不知情**（不知道專案存在）、**抗拒**（知道但反對）、**中立**、**支持**、**主導**（主動推動）。

    對每個關鍵人物問兩個問題：

    1. 他現在在哪一級？
    2. 為了讓專案成功，他需要在哪一級？

    兩者的差距就是你要做的功課。不是每個人都要變成「支持」：有些人只需要從「不知情」變成「中立」，不阻擋就夠了。

    **IT 例子**

    新監控平台上線後，維運團隊要負責告警處理。他們目前「抗拒」，因為擔心工作量增加。專案需要他們至少「支持」。具體行動可以是：讓維運主管參與告警規則設計、先在一個系統試行並統計實際告警量、提供教育訓練。

    **最常見的誤解**

    「參與 = 多寄信、多開會。」其實參與的重點是**讓對方的顧慮被處理**。寄十封信給一個抗拒的人，不如一次面對面處理他真正擔心的事。

=== "進階"

    **取捨與兩難**

    - 讓利害關係人參與越深，他們越有歸屬感，但也越可能提出新需求。參與需要配合範疇管理，見 [T-10 範疇蔓延](T-10-scope-creep.md)。
    - 參與有成本：一個關鍵主管的時間很貴，要設計「最少的接觸、最大的影響」，例如在決策點前的 15 分鐘預先溝通。

    **跨主題的互動**

    - 抗拒的心理根源見 [P-02 變革抗拒](../psychology/P-02-resistance-to-change.md)。
    - 影響力的技巧見 [P-03 沒有職權的影響力](../psychology/P-03-influence-without-authority.md)。
    - 溝通頻率與管道見 [T-21 溝通規劃](T-21-communication-planning.md)。

    **資深 PM 怎麼判斷**

    資深 PM 不會等到開會時才知道某人反對。他們的原則是：**重要會議上不該出現驚喜**。關鍵決策之前，先一對一確認每個關鍵人物的立場。

## 明天上班可以怎麼用

- 對你方格裡「重點管理」的人，各標上 C（現在）與 D（需要）。
- 落差最大的那一位，本週安排一次 15 分鐘的一對一，目的只有一個：聽他的顧慮。
- 下次重要會議前，先私下跟兩位關鍵人物確認立場。

## 小測驗

你發現某位廠區主管對新網路架構的態度是「抗拒」，原因是他擔心割接期間影響產線。專案需要他「支持」。最好的第一步是？

- A. 請他的上級要求他配合
- B. 邀請他一起審查割接計畫，並請他指定產線最能接受的時段
- C. 在週會上公開說明割接風險很低
- D. 先跳過他的廠區，最後再處理

??? success "看答案與解析"
    **答案是 B。**

    - **A 錯：** 壓力可能換來表面配合，但他的顧慮沒有被處理，割接當天任何小問題都會被放大。
    - **B 對：** 讓他參與決定他最在意的事（時段），把顧慮變成設計輸入，參與感會讓他從抗拒走向支持，見 [P-02 變革抗拒](../psychology/P-02-resistance-to-change.md)。
    - **C 錯：** 公開保證「風險很低」不會消除個人的擔憂，若之後出事反而損害你的信用。
    - **D 錯：** 拖延只會讓問題在最後爆發，而且最後時程更緊、可協商的空間更少。
