# T-01 專案、專案集與產品 (Project / Program / Product)

**專案是「有起點、有終點、要交付獨特成果」的一次性工作；專案集是一群互相牽動、一起管理才划算的專案；產品是活得比任何一個專案都久、持續演進的東西。**

```text
 組合 Portfolio：組織要把錢押在哪些事上
   │
   ├─ 專案集 Program：目標相同、彼此牽動
   │    ├─ 專案 A：有開始、有結束
   │    ├─ 專案 B
   │    └─ 專案 C
   │
   └─ 獨立專案 D

 產品 Product：從誕生到退場的整個生命週期
 ──────────────────────────────────────────►
   ↑ 專案 1 打造    ↑ 專案 2 改版   ↑ 專案 3 汰換
```

=== "入門"

    **白話解釋**

    | | 專案 Project | 專案集 Program | 產品 Product |
    |---|---|---|---|
    | 什麼時候結束 | 成果交付就結束 | 整體效益實現才結束 | 產品退場才結束 |
    | 成功的定義 | 範疇、時程、成本、品質達標 | 一群專案加起來產生的效益 | 使用者持續得到價值 |
    | 誰負責 | 專案經理 (Project Manager) | 專案集經理 (Program Manager) | 產品經理 (Product Manager) |

    **IT 例子**

    公司要「把舊機房搬到新機房」。

    - 新機房的網路建置是一個**專案**：有交付日期，網路通了、驗收了，專案就結束。
    - 網路建置、伺服器搬遷、應用系統切換、舊機房退役，這四件事互相卡住彼此的時程，放在一起管才能避免互相等待，這是一個**專案集**。
    - 機房裡跑的內部服務平台是一個**產品**：搬遷只是它生命中的一段，搬完之後它還要繼續維運、改版。

    **最常見的誤解**

    「專案集就是比較大的專案。」不是。判斷標準是**專案之間有沒有相依性、合在一起管理有沒有額外好處**，不是規模。一個很大但獨立的專案仍然是專案；三個小專案如果共用同一批人、同一個割接窗口，就值得當成專案集來管。

=== "進階"

    **取捨與兩難**

    - **專案思維 vs. 產品思維**：專案思維追求「準時交付、然後解散團隊」；產品思維追求「長期價值」。只用專案思維管產品，常見的後果是上線後沒人負責、技術債累積。只用產品思維管一次性的建置，則可能永遠在「再優化一下」而無法結案。
    - **專案集的代價**：多一層治理就多一層會議與報告。如果專案之間其實沒有相依性，硬包成專案集只會增加行政負擔。

    **跨主題的互動**

    - 專案集經理的權力通常比專案經理更間接，更依賴影響力，見 [P-03 沒有職權的影響力](../psychology/P-03-influence-without-authority.md)。
    - 專案集的成功是「效益」，所以它和 [T-04 商業論證與效益](T-04-business-case.md) 綁得特別緊。

    **資深 PM 怎麼判斷**

    拿到一件工作，先問三個問題：

    1. 它有明確的結束點嗎？沒有 → 這比較像產品或維運，不是專案。
    2. 它和其他工作共用資源、共用時程窗口、或彼此有交付相依嗎？有 → 考慮用專案集的方式協調。
    3. 交付之後誰接手？說不出來 → 結案時會出問題，見 [T-28 結案與移交](T-28-closure-handover.md)。

## 明天上班可以怎麼用

- 把你手上的工作列出來，各標上「專案 / 專案集的一部分 / 產品或維運」。標不出來的，就是範疇或責任還沒講清楚的地方。
- 對每個專案寫一句「這個專案在什麼條件下算結束」。寫不出來，先跟主管或發起人對齊。
- 如果你的專案和別人的專案共用割接窗口或同一批工程師，主動提議建立一張共同的相依關係表。

## 小測驗

你被指派負責「升級三個廠區的網路設備」。三個廠區由不同團隊執行，但必須共用同一批原廠工程師，且都要在同一季的停機窗口完成。最適合的管理方式是？

- A. 當成三個完全獨立的專案，各自管理
- B. 當成一個專案集，統一協調資源與窗口，三個專案各自執行
- C. 當成一個產品，持續改版
- D. 合併成一個超大專案，只用一份時程表

??? success "看答案與解析"
    **答案是 B。**

    - **A 錯：** 三者共用原廠工程師和停機窗口，各自規劃一定會撞期，最後變成搶資源，見 [T-14 資源規劃與平衡](T-14-resource-planning.md)。
    - **B 對：** 專案之間有共用資源與時程相依，合在一起協調才有好處，這正是專案集的定義。各專案仍保有自己的執行團隊和細部計畫。
    - **C 錯：** 設備升級有明確的結束點，不是持續演進的產品。
    - **D 錯：** 一份大時程表看似簡單，但三個廠區的團隊、風險、利害關係人都不同，全部塞在一起會讓每個團隊都看不清自己的責任，見 [T-19 責任分派與 RACI](T-19-raci.md)。
