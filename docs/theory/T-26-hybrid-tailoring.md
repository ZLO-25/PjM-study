# T-26 混合式與裁適 (Hybrid & Tailoring)

**混合式是在同一個專案中，依各部分的特性分別採用預測式或敏捷做法；裁適是根據專案的規模、風險、不確定性和組織環境，刻意決定流程要做到多重。**

```text
 依兩個問題決定做法

 需求確定性
  高 │  預測式           │  預測式為主
     │  （機房建置）      │  加迭代驗證
     ├───────────────────┼───────────────────
  低 │  混合式           │  敏捷
     │  （規格會變的硬體）│  （內部工具開發）
     └───────────────────┴───────────────────►
        難以分批交付         容易分批交付

 混合式專案的典型樣貌
 硬體採購、建置 ──── 預測式：計畫、基準、變更控制
 軟體、自動化   ──── 敏捷：Sprint、待辦清單
 整體治理       ──── 階段關卡 + 定期檢視
```

=== "入門"

    **白話解釋**

    **裁適**要考慮的因素：

    - **規模**：人數、預算、時間長度。
    - **風險與影響**：出錯的代價有多大？能不能回退？
    - **不確定性**：需求清楚嗎？技術成熟嗎？
    - **組織環境**：法規、稽核要求、文化。
    - **團隊**：成員經驗、是否全職、是否同地辦公。

    **IT 例子**

    「系統汰換」專案中：

    - 新系統的介面與報表 → 敏捷：每兩週給使用者看一次，邊做邊調。
    - 資料移轉與切換 → 預測式：詳細計畫、演練、回退方案、固定切換日。
    - 硬體採購 → 預測式：交期長，要提早下單。
    - 整體 → 用階段關卡串起來，讓管理層有固定的決策點。

    **最常見的誤解**

    「混合式 = 兩種都做一半。」混合式不是折衷，而是**每個部分都選最適合的做法**，然後設計它們之間的介面（例如：敏捷團隊的增量要在什麼時間點進入預測式的整合測試）。

=== "進階"

    **取捨與兩難**

    - 混合式的難點在介面：敏捷部分的範疇在變，預測式部分的時程卻固定。需要明確的同步點，例如「每個季度的整合窗口」。
    - 裁適要能被說明。稽核或主管問「為什麼這個專案沒有做 X」時，你要有理由，最好寫在專案計畫裡。
    - **什麼時候不適用混合式**：專案很小、或性質單純時，混合式反而增加協調成本，選一種做法就好。

    **跨主題的互動**

    - 裁適是 PMBOK 7 的核心原則之一，見 [T-02 PMBOK 7 原則與績效領域](T-02-pmbok7-principles-domains.md)。
    - 兩種做法的細節見 [T-25 敏捷價值與 Scrum](T-25-agile-scrum.md)、[T-11 時程網路與要徑](T-11-critical-path.md)。
    - 節奏設計見 [W-17 混合式專案節奏設計](../practice/W-17-hybrid-cadence.md)。

    **資深 PM 怎麼判斷**

    資深 PM 裁適時，先問「這個專案最可能怎麼失敗？」，然後把管控力氣放在那裡。如果最大的風險是需求錯誤，就加強迭代與使用者回饋；如果最大的風險是割接失敗，就加強演練與回退。

## 明天上班可以怎麼用

- 把你的專案拆成三到五個部分，各自標上「預測式 / 敏捷」，並寫一句理由。
- 寫一段「本專案裁適說明」放進專案計畫：哪些流程加重、哪些簡化、為什麼。
- 找出兩種做法之間的交接點，在時程上標出來。

## 小測驗

你負責「導入新的網路自動化平台」：要採購伺服器（交期 8 週）、開發自動化腳本（需求會隨工程師試用而改變）、最後在生產環境上線（需要變更審查）。最適合的做法是？

- A. 全部用預測式，開工前把所有腳本需求寫完
- B. 全部用敏捷，每兩週交付
- C. 伺服器採購與上線審查用預測式，腳本開發用短迭代並讓工程師試用，兩者在上線前的整合點同步
- D. 不需要規劃，邊做邊看

??? success "看答案與解析"
    **答案是 C。**

    - **A 錯：** 腳本需求會隨試用改變，事前寫完的規格很快就會過時。
    - **B 錯：** 硬體採購無法「每兩週交付」，上線審查也有固定流程。
    - **C 對：** 每個部分選最適合的做法，再設計同步點，這就是混合式。
    - **D 錯：** 硬體交期 8 週，不規劃就會讓採購變成要徑上的延誤，見 [T-11 時程網路與要徑](T-11-critical-path.md)。
