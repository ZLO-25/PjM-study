# T-24 治理與階段關卡 (Governance & Stage Gates)

**專案治理定義了「誰有權決定什麼、依據什麼決定、出問題時找誰」；階段關卡是在專案的關鍵轉折點，正式問一次「要繼續、要調整、還是要停止」。**

```text
 構想 ─► [G1] ─► 規劃 ─► [G2] ─► 建置 ─► [G3] ─► 上線
          │               │               │
          ▼               ▼               ▼
       值得做嗎？     計畫可行嗎？    準備好上線了嗎？

 G1、G2、G3 = 關卡 1、2、3

 每個關卡的三種結果
 ┌─ 通過 Go：進入下一階段
 ├─ 有條件通過 / 修正：補完特定項目後再進
 └─ 停止 Kill：止損，資源轉去別處
```

=== "入門"

    **白話解釋**

    治理架構常見的角色：

    - **指導委員會 (Steering Committee)**：高階主管組成，決定方向、預算、重大取捨。
    - **發起人 (Sponsor)**：專案的最終負責人，替專案爭取資源、排除組織障礙。
    - **PM**：執行與整合，向發起人與委員會報告。
    - **PMO（專案管理辦公室）**：提供標準、工具、跨專案的監督，各組織的角色差異很大。

    階段關卡需要事先定義**進入條件**。例如「關卡 3：上線準備」的條件可能是：所有 P1 缺陷已修正、回退方案已演練、維運團隊已完成訓練、驗收標準已確認。

    **IT 例子**

    網路汰換專案在「關卡 2」發現，新設備的報價比預估高 40%。這時候關卡的價值就出來了：委員會可以決定追加預算、縮小範圍（先換核心、邊緣明年再換），或暫停專案重新評估。如果沒有這個關卡，專案會一路做下去，直到預算用完才發現問題。

    **最常見的誤解**

    「關卡只是走個形式，大家都會通過。」如果一個組織的關卡從來沒有停掉過任何專案，那它的關卡就沒有在做決策，只是在蓋章。

=== "進階"

    **取捨與兩難**

    - 關卡太多會拖慢專案，太少又失去控制。依專案的規模與風險裁適，見 [T-26 混合式與裁適](T-26-hybrid-tailoring.md)。
    - 停止一個專案在心理上很難，因為大家已經投入很多，見 [P-08 沉沒成本與承諾升級](../psychology/P-08-escalation-of-commitment.md)。好的治理會事先寫下「什麼條件下應該停」，降低當下的心理壓力。
    - 委員會成員意見太一致時，可能是團體迷思，見 [P-14 團體迷思](../psychology/P-14-groupthink.md)。

    **跨主題的互動**

    - 關卡上要重新檢查商業論證，見 [T-04 商業論證與效益](T-04-business-case.md)。
    - 變更的核准權屬於治理的一部分，見 [T-23 整合變更控制](T-23-change-control.md)。

    **資深 PM 怎麼判斷**

    資深 PM 會把關卡會議當成「幫決策者做決定」的場合：準備好選項、每個選項的代價、自己的建議，而不只是報告進度。委員會最怕的不是壞消息，而是沒有選項的壞消息。

## 明天上班可以怎麼用

- 弄清楚你的專案「誰有權停掉它」。如果答不出來，這就是治理的缺口。
- 為下一個階段轉換寫下三到五條進入條件，請發起人確認。
- 下次報告重大問題時，準備至少兩個選項和你的建議。

## 對照案例

- [C-03 FBI Virtual Case File](../cases/C-03-fbi-virtual-case-file.md)：專案最終被終止，是討論「什麼時候該停」的經典素材。
- [C-05 Berlin Brandenburg 機場](../cases/C-05-berlin-brandenburg-airport.md)：多方共同擁有的專案，治理與決策責任分散。
- [C-06 英國 NHS NPfIT](../cases/C-06-nhs-npfit.md)：大型計畫在多年後被拆解。

## 小測驗

專案進入「上線準備」關卡。測試結果顯示仍有兩個 P1 缺陷，修復需要一週，但上線日已經對外公告。關卡的進入條件包含「無未解決的 P1 缺陷」。PM 最適合的做法是？

- A. 隱瞞缺陷，讓專案通過關卡
- B. 自行決定延後上線
- C. 如實報告缺陷與影響，提出選項（延後一週、有條件上線並準備回退、縮小上線範圍），由委員會決定
- D. 修改進入條件，把 P1 改成「可接受」

??? success "看答案與解析"
    **答案是 C。**

    - **A 錯：** 隱瞞讓關卡失去意義，上線後出事的責任也會更大，見 [P-15 壞消息上報延遲](../psychology/P-15-mum-effect.md)。
    - **B 錯：** 對外公告的日期是組織層級的承諾，延後的決定權不在 PM。
    - **C 對：** 關卡的目的就是讓有權者在完整資訊下做決定，PM 提供選項與建議。
    - **D 錯：** 為了通過而修改標準，等於取消了品質關卡。如果條件真的不合理，應該透過正式程序討論，而不是在關卡當下偷改。
