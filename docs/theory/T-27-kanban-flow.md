# T-27 看板與流動 (Kanban & Flow)

**看板 (Kanban) 是把工作的流動視覺化，並限制「同時進行中的工作量」；它不用固定的衝刺週期，而是讓工作持續、平穩地從「待辦」流到「完成」。**

```text
 待辦      分析(2)    進行中(3)   審查(2)    完成
 ─────     ───────    ─────────   ───────    ─────
 [ ]       [A]        [C]         [F]        [H]
 [ ]       [B]        [D]                    [I]
 [ ]                  [E]                    [J]
 [ ]
                      ↑
            括號內是 WIP 上限
            進行中已滿 3 張 → 不能再拉新的
            → 大家先幫忙把卡片往右推
```

=== "入門"

    **白話解釋**

    看板的核心做法：

    1. **視覺化工作**：每件工作一張卡，依階段放在不同欄。
    2. **限制在製品 (Work in Progress, WIP)**：每一欄設上限，滿了就不能再拉新工作。
    3. **管理流動**：觀察卡片卡在哪裡，持續改善。
    4. **明確規則**：例如「什麼條件下可以從審查移到完成」。

    **常用指標**

    - **前置時間 (Lead Time)**：從提出需求到完成的時間。
    - **週期時間 (Cycle Time)**：從開始動工到完成的時間。
    - **吞吐量 (Throughput)**：每段時間完成多少件。

    **IT 例子**

    網路團隊的日常需求（開防火牆規則、新增 VLAN、設備更換）來源不固定、大小不一，很適合用看板。設定「進行中」上限 3 張，可以避免每個人同時開十張單、每張都做一半。

    **最常見的誤解**

    「看板就是把便利貼貼在牆上。」只有視覺化沒有 WIP 上限，就只是任務清單。WIP 上限才是讓流動變快的關鍵：少做幾件，反而完成得更快。

=== "進階"

    **取捨與兩難**

    - **看板 vs. Scrum**：Scrum 適合有明確產品目標、可以規劃一段時間工作的團隊；看板適合需求持續湧入、優先順序經常變動的團隊（例如維運、支援）。兩者也可以混用。
    - 設定 WIP 上限的初期會讓人不舒服，因為「有人閒著」。但閒著的人去幫忙解決瓶頸，整體會更快。
    - **什麼時候不適用**：大型一次性建置專案的主體工作，用看板難以看出整體進度與要徑。

    **跨主題的互動**

    - 和 Scrum 的比較見 [T-25 敏捷價值與 Scrum](T-25-agile-scrum.md)。
    - 混合式專案中，看板常用來管理「專案中的日常支援工作」，見 [T-26 混合式與裁適](T-26-hybrid-tailoring.md)。
    - 多工對人的影響見 [T-14 資源規劃與平衡](T-14-resource-planning.md)。

    **資深 PM 怎麼判斷**

    資深 PM 看看板時不只看「完成了多少」，而是看「卡片在哪一欄停留最久」。停留最久的那一欄就是瓶頸，改善它的效果最大。

## 明天上班可以怎麼用

- 把你團隊目前進行中的工作全部列出來。如果每人超過三件，試著設一個 WIP 上限。
- 記錄十張工單從開始到完成的時間，找出最常卡住的階段。
- 在專案中，用一個小看板管理「割接前的準備事項」，讓團隊一眼看到哪裡卡住。

## 小測驗

你的團隊看板顯示：「審查」欄堆了 8 張卡（上限 2），「進行中」只有 1 張。最合理的判斷與行動是？

- A. 團隊太閒，應該多拉新工作進「進行中」
- B. 審查是瓶頸，應該暫停拉新工作，讓有能力的人先協助審查，並找出審查卡住的原因
- C. 提高審查欄的 WIP 上限到 10
- D. 把審查步驟取消

??? success "看答案與解析"
    **答案是 B。**

    - **A 錯：** 再拉新工作只會讓審查堆得更多，整體完成速度不會變快。
    - **B 對：** 看板的原則是「先完成、再開始」。瓶頸在審查，資源就該往那裡集中。
    - **C 錯：** 提高上限只是讓問題看不見，瓶頸仍然存在。
    - **D 錯：** 審查是品質控制的一環，取消會把問題延到上線後，見 [T-17 品質規劃與品質成本](T-17-quality-planning.md)。
