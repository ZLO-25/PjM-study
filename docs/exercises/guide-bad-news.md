# 引導練習：如何回報一個壞消息

**情境：** 你的專案過去四週週報都是綠燈。今天下午，網路組長告訴你：新設備的相容性測試失敗，原廠說要兩到四週才能提供修正韌體。這項工作在要徑上，原定一個月後的上線日很可能受影響。你的處長下週一要向副總報告各專案狀態。今天是週四。

## 問題 1：這件事現在是風險還是議題？燈號應該是什麼？

??? tip "提示"
    測試失敗已經發生了嗎？它會影響核准的時程嗎？

??? note "參考思路"
    測試失敗已經發生，是**議題**；它在要徑上，很可能影響上線日，是否會延誤則仍是**風險**。燈號至少是**黃燈**；如果你判斷 PM 自己無法解決、需要處長決策（例如是否延期），就是**紅燈**。參考 [T-16 風險、議題與假設](../theory/T-16-risk-issue-assumption.md)、[T-22 狀態報告與紅黃綠燈](../theory/T-22-status-reporting.md)。

## 問題 2：你心裡可能會有哪些「想等一下再說」的理由？

??? tip "提示"
    誠實地列出來，這些念頭很正常。

??? note "參考思路"
    - 「原廠說兩週，也許會更快，到時候就不用報了。」
    - 「連續四週綠燈，突然變黃很難看。」
    - 「我想先找到解法再說。」
    - 「處長最近很忙。」

    這些都是緘默效應的典型想法。但處長週一就要向上報告，如果他在那之後才知道，他會非常被動。參考 [P-15 壞消息上報延遲](../psychology/P-15-mum-effect.md)。

## 問題 3：你應該在什麼時候、用什麼方式告訴處長？

??? tip "提示"
    書面還是口頭？在他向副總報告之前還是之後？

??? note "參考思路"
    **今天或明天**，**先口頭**（當面或電話），再用書面補上。一定要在週一之前，讓他有時間決定要怎麼向副總說明。參考 [P-05 向上管理](../psychology/P-05-managing-up.md)。

## 問題 4：口頭報告時，你的第一句話要怎麼說？

??? tip "提示"
    主管最怕三件事：驚喜、沒選項、不知道要他做什麼。

??? note "參考思路"
    「處長，有一件可能影響上線日的事要讓您知道，週一您報告前可能需要您決定怎麼說明。」

    接著依序：發生什麼事（三句內）→ 影響 → 選項 → 建議 → 下次更新時間。

## 問題 5：你可以提出哪些選項？

??? tip "提示"
    想一想：時程、範疇、技術方案，各有哪些可以動？

??? note "參考思路"
    - **A. 維持上線日，先上不需要新韌體的部分**，相容問題的部分延後上線。
    - **B. 上線日延後四週**，等修正韌體並完成測試。
    - **C. 改用另一款已驗證的型號**，需評估採購時間與成本。

    並附上你的建議，以及「原廠會在下週三前給出確切日期，屆時我會更新」。參考 [W-15 升級上報信](../practice/W-15-escalation.md)。

## 問題 6：回到團隊，你要對網路組長說什麼？

??? tip "提示"
    他今天把壞消息告訴你，你希望他下次還會這樣做嗎？

??? note "參考思路"
    「謝謝你今天就告訴我，這讓處長能在週一前有準備。」用行動證明「早說是對的」，才能讓團隊持續把壞消息往上傳。參考 [P-11 心理安全感](../psychology/P-11-psychological-safety.md)。

??? abstract "總結"
    回報壞消息的五個原則：

    1. **定性清楚**：是議題還是風險、燈號是什麼。
    2. **察覺自己的拖延念頭**，它們很正常，但不要被它們決定。
    3. **在主管需要用到之前**讓他知道，**先口頭再書面**。
    4. **結論先行，帶著選項與建議**，說明下次更新時間。
    5. **感謝帶來壞消息的人**，保護資訊流。
