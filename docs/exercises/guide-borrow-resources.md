# 引導練習：跟職能經理借人

**情境：** 你負責資料中心網路擴充專案，下個月的核心設備設定需要部門裡唯一熟悉現有架構的資深工程師投入至少兩週。你去找他的職能經理，對方說：「他這個月要支援維運，還有另一個專案在排他，你們自己協調。」你沒有權力指派他，而這項工作在要徑上。

**怎麼用這一頁：** 每一題先自己想，再點開提示與參考思路。

## 問題 1：去談之前，你手上應該先有哪些數字？

??? tip "提示"
    職能經理面對的是「三個人都要同一個人」。他需要什麼資訊才能排優先順序？

??? note "參考思路"
    至少三樣：

    - **要多少**：幾個工作天、哪兩週、是全職還是半天。
    - **為什麼是他**：哪些工作只有他能做，哪些其實可以由別人做、由他審查。
    - **延誤的後果**：這項工作在要徑上，晚一週就晚一週上線，影響哪個已經對外承諾的日期。

    帶著「我需要他」去談是立場；帶著「這兩週需要 6 個工作天，其中 2 天只有他能做」去談是利益與客觀標準。參考 [T-14 資源規劃與平衡](../theory/T-14-resource-planning.md)、[T-11 時程網路與要徑](../theory/T-11-critical-path.md)。

## 問題 2：職能經理說「你們自己協調」，他真正的顧慮可能是什麼？

??? tip "提示"
    他要同時對維運穩定、另一個專案、以及這位工程師的負荷負責。

??? note "參考思路"
    - 他不想當裁判，因為不論怎麼排都會得罪一個 PM。
    - 他怕維運出事時沒人在。
    - 他擔心這位工程師已經被排滿，再加會離職或出錯。
    - 他可能根本不知道兩個專案各需要多少，因為沒有人給過他一張表。

    這些都是可以一起解決的問題，而不是「他不配合」。參考 [P-01 利害關係人的動機與恐懼](../psychology/P-01-stakeholder-motives.md)、[T-20 矩陣式組織](../theory/T-20-matrix-organization.md)。

## 問題 3：你應該單獨去談，還是邀另一位 PM 一起？

??? tip "提示"
    如果你單獨談贏了，另一位 PM 下週會做什麼？

??? note "參考思路"
    邀另一位 PM 與職能經理開一次三方會議，把兩個專案的需求、時間、是否在要徑上、延誤影響放在同一張表上。這樣職能經理不是在「選邊」，而是在用客觀標準排序；另一位 PM 也不會覺得被繞過。[C-12【模擬】跨部門資源爭奪](../cases/C-12-sim-resource-conflict.md) 就是這個做法。

    單獨談的風險：你贏了，但下週另一位 PM 私下找工程師，他兩邊都答應，兩邊都延誤，見 [P-16 新手 PM 的冒牌者感與討好傾向](../psychology/P-16-rookie-pm-traps.md)。

## 問題 4：如果對方還是說不行，你的最佳替代方案 (BATNA) 是什麼？

??? tip "提示"
    談判前先想好「談不成我會怎麼辦」，你才不會在桌上什麼都答應。

??? note "參考思路"
    可能的替代方案，由便宜到貴：

    - **拆工作**：只有他能做的 2 天保留給他，其他 4 天由另一位工程師做、他花半天審查。
    - **改順序**：把要徑上不依賴他的工作先做，替他的工作爭取兩週浮時。
    - **外部支援**：原廠或外包做設定，他做審查；需要評估費用與交期。
    - **升級**：帶著負荷表與影響，請發起人和職能經理的主管決定優先順序。這是最後手段，不是第一步。

    有了替代方案，你在談的時候就有底線；沒有替代方案，你只能接受對方開的條件。參考 [P-04 原則式談判與 BATNA](../psychology/P-04-principled-negotiation.md)。

## 問題 5：你能給職能經理什麼？

??? tip "提示"
    沒有職權的影響力來自交換。他在乎什麼？

??? note "參考思路"
    - **減少他的麻煩**：你來做負荷表、你來邀另一位 PM，他只要做決定。
    - **長期的好處**：建議安排一位資淺工程師跟著學，下次就不是只有一個人會。這解決的是他的長期風險。
    - **可見度**：在狀態報告中寫明「感謝網路部門支援」，讓他的主管看到。
    - **承諾**：未來對這位工程師的需求，一律透過他排程，不再私下直接要求。

    參考 [P-03 沒有職權的影響力](../psychology/P-03-influence-without-authority.md)。

## 問題 6：談成之後，你要留下什麼紀錄？

??? tip "提示"
    口頭的「好，給你兩週」在三週後會長什麼樣子？

??? note "參考思路"
    - 一封會後信給職能經理與另一位 PM：哪兩週、幾個工作天、誰做什麼、誰審查、如果維運出事的例外處理。
    - 在 [RAID 日誌](../practice/W-09-raid-log.md) 新增一條**相依**：「資深工程師於 X 到 Y 投入，由職能經理確認」，每週追蹤。
    - 在資源計畫中更新他的負荷，讓下一次需求有依據。

    參考 [W-21 會議紀錄與行動項目追蹤](../practice/W-21-meeting-notes-action-items.md)。

??? abstract "總結"
    跟職能經理借人的六個步驟：

    1. **先算清楚**：要多少、為什麼是他、延誤的後果。
    2. **理解他的顧慮**：他不是不配合，是沒有資訊、不想當裁判。
    3. **把競爭者拉上桌**：三方會議，用客觀標準排序，不是選邊。
    4. **準備替代方案**：拆工作、改順序、外部支援、升級。
    5. **給對方東西**：減少麻煩、長期好處、可見度、承諾。
    6. **留下紀錄**：會後信、RAID 相依、負荷更新。
