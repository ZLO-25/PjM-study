# C-01 Denver 國際機場自動化行李系統 (Denver International Airport Baggage System)

**一句話摘要：一套規模前所未見的全自動行李系統，在範圍擴大、時程被機場開幕日綁死的情況下開發，最後拖延了整座機場的開幕，並在多年後被放棄。**

!!! note "閱讀說明"
    本頁把內容分成「已知事實」（有公開報告或廣泛報導支持）與「推論詮釋」（本手冊的分析）。數字以頁尾的公開來源為準；來源之間說法不一致時，本頁採用保守的描述。

```text
 時間線（概略）

 1989  機場開工
   │
 1990s 初  決定採用全機場自動化行李系統
   │       （原先只規劃給單一航空公司）
   │
 1993  原定開幕 ── 延期
   │
 1994  媒體展示時系統故障，延期再延期
   │   決定加建傳統行李系統作為備援
   │
 1995  機場開幕（較原定晚約 16 個月）
   │   自動化系統只在部分航廈使用
   │
 2005  最後使用的航空公司停用自動化系統
```

## 背景

=== "已知事實"

    - Denver 國際機場在 1980 年代末期開始興建，用來取代舊機場。
    - 機場決定採用一套橫跨整座機場的自動化行李系統，以軌道小車運送行李。依據美國審計總署 (GAO) 的報告，系統的範圍與複雜度在當時沒有前例。
    - 行李系統原先由一家主要航空公司為自己的航廈規劃，後來擴大為全機場使用。
    - 機場原定在 1993 年秋季開幕，因行李系統問題多次延期，最終於 1995 年 2 月開幕。GAO 的報告與後續研究普遍將行李系統列為延期的主要原因。
    - 延期期間，機場決定加建一套傳統的行李輸送系統作為備援。
    - 自動化系統在開幕後只在有限範圍使用，最後於 2005 年左右被完全停用。

=== "推論詮釋"

    - 系統的開發時間相對於它的複雜度來說非常短，而且開幕日期在行李系統的設計確定之前就已經公告，形成「固定時程、擴大範疇」的組合。
    - 在學術研究（例如 Montealegre 與 Keil 對此案的分析）中，本案常被用來說明「承諾升級」與「如何從失敗的專案中脫身（降級）」。

## 關鍵決策點

1. **決定採用全機場自動化系統**：選擇了一項在這個規模上未經驗證的技術。
2. **範圍擴大但時程不變**：從單一航空公司擴大到全機場，開幕日沒有相應調整。
3. **建築與行李系統平行進行**：行李系統需要的空間、轉彎、坡度，與已經在建的建築互相限制。
4. **延期後加建備援系統**：這是讓機場最終能開幕的關鍵決策，也是一種「降級」。

## 出了什麼事

- **已知**：測試與媒體展示期間，系統出現行李被拋出、卡住、送錯等問題，這些畫面被廣泛報導。
- **已知**：機場延期開幕，期間產生大量額外的財務成本（金額依來源不同，請參考 GAO 報告）。
- **推論**：真正的問題不只是技術，而是「在技術不確定性最高的地方，給了最不能變動的時程」。

## 對應理論 (T)

- [T-10 範疇蔓延](../theory/T-10-scope-creep.md)：系統範圍擴大，時程卻被綁在開幕日。
- [T-15 風險管理](../theory/T-15-risk-management.md)：採用未經驗證規模的技術，且備案在後期才建立。
- [T-23 整合變更控制](../theory/T-23-change-control.md)：建造期間的設計變更累積效應。
- [T-11 時程網路與要徑](../theory/T-11-critical-path.md)：行李系統成為整座機場開幕的要徑。

## 對應心理 (P)

- [P-14 團體迷思](../psychology/P-14-groupthink.md)：對新技術的信心，可能讓警訊未被充分討論（推論）。
- [P-08 沉沒成本與承諾升級](../psychology/P-08-escalation-of-commitment.md)：持續投入一套問題不斷的系統。
- [P-07 規劃謬誤與樂觀偏誤](../psychology/P-07-planning-fallacy.md)：以前所未見的複雜度，搭配緊迫的時程。

## 反事實推演

如果你是當時的 PM，在以下時間點可以怎麼做？（以下是推演，不是事實）

- **範圍擴大時**：要求同步調整開幕日，或把行李系統拆成「先上一個航廈、驗證後再擴大」的分階段做法。
- **設計初期**：在合約與計畫中就要求準備傳統備援系統，作為風險回應中的「接受並準備應變」。
- **第一次測試失敗後**：設定明確的「停止條件」，例如「若某日前無法達到某可靠度，就啟動備援方案開幕」，而不是在多次延期後才決定。

## 可帶走的教訓

1. **不要在技術最不確定的地方，放最不能動的時程。**
2. **範圍擴大，時程與預算一定要重新評估**，這是變更控制的核心。
3. **為高風險的創新準備備案**，而且要在早期就準備。
4. **「降級」也是一種成功**：及時改用備援，讓機場得以開幕。

## 小測驗

在這個案例中，哪一個做法最可能在早期大幅降低風險？

- A. 加更多工程師趕工
- B. 先在單一航廈實作並驗證，成功後再擴大到全機場，同時準備傳統備援
- C. 延長每天的施工時間
- D. 更換行李系統的顏色與品牌

??? success "看答案與解析"
    **答案是 B。**

    - **A 錯：** 在技術問題未解決時加人，常常無法縮短時程，甚至因溝通成本上升而更慢。
    - **B 對：** 分階段驗證降低了技術風險的規模，備援則讓開幕日不再完全依賴未經驗證的系統，見 [T-15 風險管理](../theory/T-15-risk-management.md)、[T-26 混合式與裁適](../theory/T-26-hybrid-tailoring.md)。
    - **C 錯：** 與 A 相同，只是加大投入，不改變風險結構。
    - **D 錯：** 與問題無關。
