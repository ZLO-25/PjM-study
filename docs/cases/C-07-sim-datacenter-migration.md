# C-07【模擬】資料中心遷移 (Data Center Migration)

**一句話摘要：一家中型企業要在 9 個月內把 300 台伺服器從舊機房遷到新機房；第一波遷移因為漏掉一個應用相依而失敗，團隊調整做法後，後續波次順利完成。**

!!! info "這是模擬案例"
    本案例為教學設計的虛構情境，不對應任何真實組織、人員或事件。

```text
 遷移波次設計（調整後）

 波次 0   盤點與相依關係調查（新增）
   │
 波次 1   低風險：測試與開發環境
   │
 波次 2   中風險：內部系統
   │
 波次 3   高風險：對外服務、財務系統
   │
 退役     舊機房設備除役、合約終止

 每一波：準備 ─► 演練 ─► 遷移 ─► 驗證 ─► 復盤
```

## 背景

舊機房租約將在 9 個月後到期，不續約。PM 由基礎架構部門指派，團隊包含網路、系統、儲存、應用窗口與機房廠商。原始計畫依「機櫃位置」分成三波遷移，以減少搬運次數。

## 關鍵決策點

1. **依機櫃位置分波**，而不是依應用相依關係。
2. **省略獨立的相依關係調查**，因為「CMDB（設定管理資料庫）裡有資料」。
3. **第一波失敗後**，決定暫停兩週、補做盤點，並重新設計波次。

## 出了什麼事

第一波遷移完成後，一個內部報表系統無法運作。原因是它在凌晨會呼叫一台仍在舊機房的資料庫，而這個相依關係不在 CMDB 中。由於兩個機房之間的延遲較高，報表批次在凌晨逾時，隔天早上業務單位才發現。

團隊在當天回退了報表系統，並決定：

- 暫停兩週，用網路流量分析補做相依關係盤點。
- 把波次改成依「應用群組」設計，相依的系統放在同一波。
- 每一波都加入演練與完整的回退方案。

後續三波都在窗口內完成。舊機房在租約到期前一個月完成除役。

## 反事實推演

- 如果一開始就把「CMDB 資料完整」列為假設，並安排驗證（例如流量分析），第一波失敗可能可以避免。
- 如果第一波選的是真正低風險的環境（測試環境），即使出錯，影響也會小很多。

## 可帶走的教訓

1. **把「資料是完整的」當作假設，而不是事實。**
2. **遷移的分組依據應該是相依關係，而不是物理位置。**
3. **第一波要選最能承受失敗的系統**，把它當成學習的機會。
4. **暫停兩週補做功課**，比硬撐下去更快。

## 小測驗

第一波失敗後，PM 有兩個選擇：(1) 照原計畫繼續第二波，同時補做盤點；(2) 暫停兩週補做盤點，重新設計波次。考量租約還有 7 個月，哪一個比較合理？

- A. 選 (1)，時間寶貴
- B. 選 (2)，因為原計畫的分波方式已被證明有結構性問題，繼續執行可能重複同樣的失敗；而 7 個月的時間足以吸收兩週的暫停
- C. 兩個都不選，直接一次搬完
- D. 延長舊機房租約

??? success "看答案與解析"
    **答案是 B。**

    - **A 錯：** 原計畫的問題不是偶發，而是分組方式本身有缺陷。繼續執行可能讓第二波出現更嚴重的失敗。
    - **B 對：** 問題是結構性的，而且時程有空間吸收暫停，見 [T-11 時程網路與要徑](../theory/T-11-critical-path.md) 的浮時概念。
    - **C 錯：** 一次搬完把所有風險集中在一個窗口，與分波的目的相反。
    - **D 錯：** 題目設定租約不續約；即使可以，也應該先評估是否真的需要。
