# C-10【模擬】跨廠區建置 (Multi-Site Network Buildout)

**一句話摘要：一個在三個廠區同步建置新網路的專案，因為各廠區主管的參與度與標準不同，進度出現明顯落差；PM 透過統一的章程、RACI 與溝通節奏，讓三個廠區重新對齊。**

!!! info "這是模擬案例"
    本案例為教學設計的虛構情境，不對應任何真實組織、人員或事件。

```text
 三個廠區的狀態（第 8 週）

 廠區 A   ████████████░░░░  75%   主管全力支持
 廠區 B   ██████░░░░░░░░░░  40%   主管「等總部指示」
 廠區 C   ████████░░░░░░░░  50%   要求用自己的標準

 PM 的介入
 ┌─ 重新發布章程：統一目標與標準例外流程
 ├─ 三廠區共同的 RACI
 ├─ 每週 30 分鐘的三廠區聯合站會
 └─ 進度公開在共用看板上
```

## 背景

公司要在三個廠區建置新的網路架構，共用同一份設計與同一批原廠工程師，預計 6 個月完成。PM 隸屬總部 IT，三個廠區各有自己的 IT 主管，不歸 PM 管理。專案啟動時只有總部的發起人簽了章程，三位廠區主管只收到一封通知信。

## 關鍵決策點

1. **啟動時**：沒有讓三位廠區主管參與章程與啟動會議。
2. **第 8 週**：PM 發現三個廠區進度差距很大，原因各不相同。
3. **PM 的選擇**：不直接請發起人施壓，而是先一對一拜訪三位主管。
4. **重新啟動**：召開三廠區聯合的「重新啟動會議」，共同修訂 RACI 與標準例外流程。

## 出了什麼事

一對一拜訪發現：

- **廠區 B** 主管以為這是總部的專案，他的團隊只是「配合」，所以一直在等指示。他其實願意投入，但沒人告訴他他是自己廠區的 A（當責者）。
- **廠區 C** 主管認為總部的設計不符合他們廠區的特殊需求（某些產線設備需要特定的網路隔離），他的顧慮是合理的。

重新啟動會議中：

- 三位主管在 RACI 中各自成為「自己廠區建置」的 A，PM 是「整體整合與標準」的 A。
- 建立「標準例外申請」流程：廠區可以提出例外，由設計審查小組評估，避免各自為政。
- 每週一次 30 分鐘的三廠區聯合站會，大家看同一個進度看板。

第 16 週時，三個廠區的進度差距縮小到兩週內，最終專案晚了三週完成，原因主要是廠區 C 的例外設計。

## 反事實推演

- 如果第一週就讓三位主管參與章程與啟動會議，廠區 B 的誤解與廠區 C 的顧慮可能在啟動時就浮現。
- 如果 PM 在第 8 週直接請發起人施壓，可能換來表面配合，但廠區 C 的合理需求會被壓下，之後可能在上線時出問題。

## 可帶走的教訓

1. **跨單位專案，每個單位的主管都要參與啟動。**
2. **「配合」與「當責」差很多**，要在 RACI 中寫清楚。
3. **統一標準需要例外流程**，否則例外會以「各自為政」的方式出現。
4. **公開的共同進度**能自然產生同儕壓力，比上級施壓更持久。

## 小測驗

第 8 週發現廠區 B 進度落後。以下哪一個是最好的第一步？

- A. 請發起人寄信要求廠區 B 加速
- B. 在週報中標記廠區 B 為紅燈
- C. 先和廠區 B 主管一對一聊，了解落後的原因與他對自己角色的理解
- D. 派總部工程師直接去廠區 B 做

??? success "看答案與解析"
    **答案是 C。**

    - **A 錯：** 在不了解原因前施壓，可能誤傷一位其實願意配合的主管。
    - **B 錯：** 公開標紅燈卻沒先溝通，會讓對方覺得被公開指責。燈號可以更新，但要先溝通。
    - **C 對：** 先了解原因，才知道要處理的是能力、資源、意願，還是角色誤解，見 [P-01 利害關係人的動機與恐懼](../psychology/P-01-stakeholder-motives.md)。
    - **D 錯：** 越過廠區主管直接做，會破壞他的權責，也讓之後的維運交接更困難。
