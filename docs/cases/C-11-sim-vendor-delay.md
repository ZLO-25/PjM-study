# C-11【模擬】供應商交期延誤 (Vendor Delivery Delay)

**一句話摘要：一批要徑上的光模組，供應商在原定到貨日前一週才通知延誤四週；PM 事後發現，供應商的業務其實早在三週前就知道可能延誤，只是沒有說。**

!!! info "這是模擬案例"
    本案例為教學設計的虛構情境，不對應任何真實組織、人員或事件。

```text
 資訊流的落差

 第 0 週   下單，承諾 8 週到貨
 第 5 週   原廠通知供應商：產能吃緊
           供應商業務：「應該還來得及」 ← 沒有通知
 第 7 週   確定延誤
           供應商通知 PM：延誤四週
 第 7 週   PM：割接窗口已申請、團隊已排班

 若在第 5 週就知道
 → 還有 3 週可以找替代來源、調整割接順序
```

## 背景

網路升級專案需要 200 個光模組，訂單由採購部門下給一家經銷商。光模組在要徑上：沒有它，第二階段的割接無法進行。PM 在風險登錄表中寫了「供應商延誤」，但回應策略只寫「持續追蹤」，每兩週由採購窗口詢問一次。

## 關鍵決策點

1. **風險回應**：只有「追蹤」，沒有觸發條件與備案。
2. **第 7 週接到延誤通知**：PM 必須決定是延後割接、尋找替代來源，還是調整割接順序。
3. **與供應商的協商**：用什麼方式談，才能既解決眼前的問題、又改善未來的資訊流。

## 出了什麼事

PM 在接到通知後：

1. 把它從風險轉成議題，指定採購窗口與網路負責人共同找對策。
2. 調整割接順序：先做不需要新光模組的區段，讓兩週的工作可以繼續。
3. 和供應商協商時，先確認自己的 BATNA：另一家經銷商有約 80 個現貨，價格高 15%。
4. 和供應商談成：先從其他客戶的庫存中調撥 120 個，剩下的 80 個向另一家購買現貨，供應商分擔部分價差。
5. 在合約與溝通協議中加入：「任何可能影響交期的訊息，須在得知後 3 個工作天內通知。」

最終第二階段割接只延後一週。

## 反事實推演

- 如果風險登錄表中為這項風險設定了觸發條件（例如「到貨前 4 週未取得出貨確認，即啟動替代來源詢價」），PM 可能在第 4 週就開始準備備案。
- 如果一開始就和供應商約定交期訊息的通知時限，第 5 週的訊息可能就會傳到 PM 手上。

## 可帶走的教訓

1. **要徑上的外部相依，要有觸發條件與備案。**
2. **緘默效應不只發生在組織內部**，也發生在供應商身上；用合約和溝通協議降低它。
3. **談判前先找到 BATNA**，你會更有底氣，也更容易談出創造性的方案。
4. **調整工作順序**常常是吸收延誤最便宜的方法。

## 小測驗

從這個案例來看，原本風險登錄表中「持續追蹤」最大的問題是什麼？

- A. 追蹤的頻率不夠高
- B. 沒有觸發條件與具體的備案行動，所以即使追蹤到訊號，也不知道何時該行動、要做什麼
- C. 不應該追蹤供應商
- D. 應該由 PM 自己追蹤，不該交給採購

??? success "看答案與解析"
    **答案是 B。**

    - **A 錯：** 頻率提高有幫助，但如果供應商不說，問再多次也得不到資訊；而且沒有觸發條件時，得到訊號也不知道該做什麼。
    - **B 對：** 風險回應需要「觸發條件 + 行動 + 負責人」，見 [W-08 風險登錄表](../practice/W-08-risk-register.md)。
    - **C 錯：** 追蹤是必要的，只是不夠。
    - **D 錯：** 採購窗口追蹤是合理的分工，重點在回應策略的設計。
