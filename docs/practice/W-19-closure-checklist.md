# W-19 結案檢查清單 (Project Closure Checklist)

**用一張清單逐項確認交付、移交、行政、學習四條線都完成，再正式宣告結案。**

```text
 結案的四條線

 ┌─ 交付：驗收簽核、遺留項目清單
 ├─ 移交：文件、帳號、監控、保固、聯絡窗口
 ├─ 行政：合約、付款、預算、資源釋放
 └─ 學習：復盤、經驗紀錄、範本更新

 四條線都打勾 ──► 結案報告 ──► 發起人簽核 ──► 結案
```

=== "入門"

    **交付**

    - [ ] 所有交付物已依驗收標準完成驗收並簽核
    - [ ] 遺留項目已列清單，並約定負責人與期限
    - [ ] 需求追溯矩陣的每一列都有最終狀態

    **移交**

    - [ ] 架構圖、設定備份、操作手冊已交給維運團隊
    - [ ] 監控與告警已設定，並由維運確認可收到
    - [ ] 管理帳號已轉移，專案人員的臨時權限已移除
    - [ ] 保固資訊（起訖日、合約編號、報修方式）已交付
    - [ ] 維運團隊已完成教育訓練
    - [ ] 移交會議已召開，維運主管已簽署移交

    **行政**

    - [ ] 廠商合約已結清，最後一筆付款已處理
    - [ ] 預算已結算，結餘已退回或說明
    - [ ] 專案成員已釋放，並已向其職能經理提供回饋
    - [ ] 專案文件已歸檔到約定位置
    - [ ] 舊設備已依規定除役（資料清除、報廢紀錄）

    **學習**

    - [ ] 復盤會議已舉行，行動已指派，見 [W-18 主持復盤會議](W-18-retrospective.md)
    - [ ] 可重複使用的範本、檢查表已更新
    - [ ] 效益追蹤的負責人與方式已確認

    **最常見的錯誤**

    只做「交付」這條線就宣告結案。三個月後，帳號沒移除、保固到期沒人知道、同樣的錯誤在下一個專案又發生一次。

=== "進階"

    **結案報告的內容**

    一到兩頁即可：

    1. 目標達成情況（對照章程的成功標準）
    2. 時程、成本、範疇的最終結果與差異說明
    3. 核准過的重大變更摘要（來自變更紀錄表）
    4. 遺留項目與負責人
    5. 主要經驗（三點）
    6. 效益追蹤安排

    **被中止的專案也要結案**

    記錄完成到哪裡、可以保留的成果、花了多少、為什麼停。這份紀錄對未來重新啟動或類似專案非常有價值。

    **資深 PM 的檢查問題**

    - 章程中的成功標準，有沒有一條是「結案後才能量測」的？誰負責追蹤？
    - 維運團隊在移交後的第一週，如果遇到問題，知道要找誰嗎？

## 明天上班可以怎麼用

- 把這份清單複製到你的專案文件夾，依專案特性增減項目。
- 和維運主管一起過一次「移交」這一段。
- 理論背景見 [T-28 結案與移交](../theory/T-28-closure-handover.md)。

## 小測驗

結案前，你發現專案成員仍保有生產設備的管理員權限。最適合的處理是？

- A. 保留，萬一之後需要支援比較方便
- B. 依移交清單移除專案人員的臨時權限，若有支援需求，改由維運團隊依正式流程申請
- C. 只移除離職人員的權限
- D. 等稽核發現再處理

??? success "看答案與解析"
    **答案是 B。**

    - **A 錯：** 保留不必要的權限是資安風險，也是常見的稽核缺失。
    - **B 對：** 結案時移除臨時權限是移交的一部分；若未來需要支援，走正式申請可以留下紀錄。
    - **C 錯：** 所有專案的臨時權限都應該檢查，不只離職人員。
    - **D 錯：** 被動等待會讓風險持續存在，被稽核發現時責任更大。
