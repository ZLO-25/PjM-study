# W-16 變更請求單 (Change Request Form)

**變更請求單把一個「我想改」變成可以被評估和決定的文件：要改什麼、為什麼、影響多大、誰核准；每一筆都進入變更紀錄表。**

```text
 變更請求的流程

 提出者填寫 ① ② ③
       │
       ▼
 PM 評估 ④ 影響分析（2–5 個工作天）
       │
       ▼
 依等級送核准 ⑤
   小：PM
   中：發起人
   大：變更委員會
       │
       ▼
 決定後 ⑥ 更新計畫、通知相關人、記錄
```

=== "入門"

    **範本**

    | 欄位 | 說明 |
    |---|---|
    | ① 編號 / 日期 / 提出者 | CR-007 / 4/12 / 業務單位窗口 |
    | ② 變更內容 | 割接時一併更換 B 棟 12 台存取交換器 |
    | ③ 原因與效益 | B 棟設備將於年底停止支援；一併更換可省一次停機 |
    | ④ 影響分析：範疇 | 新增 12 台設備的採購、設定、測試 |
    | ④ 影響分析：時程 | 採購交期 6 週；割接日需從 5/20 延到 6/17 |
    | ④ 影響分析：成本 | 設備與施工約 X 元，目前預算無此項目 |
    | ④ 影響分析：風險 | 割接範圍擴大，回退時間增加約 40 分鐘 |
    | ④ 影響分析：品質 | 需增加 B 棟的測試案例 |
    | ④ 替代方案 | 另開一期，於 Q3 單獨處理 B 棟 |
    | ⑤ 建議與等級 | 等級：大（影響交付日與預算）；PM 建議另開一期 |
    | ⑤ 決定 | 核准 / 退回 / 延後，核准者，日期 |
    | ⑥ 後續 | 更新的文件、通知的對象 |

    **變更紀錄表**

    | 編號 | 摘要 | 提出日 | 等級 | 決定 | 決定日 | 對時程影響 | 對成本影響 |
    |---|---|---|---|---|---|---|---|
    | CR-007 | B 棟交換器一併更換 | 4/12 | 大 | 延後至 Q3 | 4/19 | 0 | 0 |

    **最常見的錯誤**

    只填「變更內容」就送核准，沒有影響分析。決策者只看到好處，看不到代價。

=== "進階"

    **影響分析要誠實但有效率**

    小變更不需要寫一份長報告。依等級調整：小變更填一行就好，大變更才需要完整分析。重點是**每一筆都被記錄**。

    **變更紀錄表的價值**

    半年後有人問「為什麼專案延了兩個月」，變更紀錄表能清楚地回答：「因為核准了這五項變更，合計影響七週。」沒有這張表，延誤就會被歸咎於執行不力。

    **資深 PM 的檢查問題**

    - 已核准的變更，時程表和預算有沒有同步更新？
    - 有沒有「口頭答應過、但沒有進紀錄表」的變更？

## 明天上班可以怎麼用

- 把這個範本存起來，下一次有人提出變更時使用。
- 建立變更紀錄表，把最近一個月口頭答應過的變更補記進去。
- 和發起人確認變更等級的標準。

## 小測驗

一位使用者提出的變更：「報表多加一個欄位。」PM 評估後發現只需要半天，不影響時程與預算。依照分級原則，最適合的處理是？

- A. 送變更委員會核准
- B. PM 依授權直接核准，但仍在變更紀錄表中記錄
- C. 直接做，不需要記錄
- D. 拒絕，範疇已經凍結

??? success "看答案與解析"
    **答案是 B。**

    - **A 錯：** 小變更送委員會會拖慢流程，也浪費委員的時間。
    - **B 對：** 在授權範圍內快速核准，但留下紀錄，讓所有變更都可追溯。
    - **C 錯：** 不記錄的小變更累積起來就是範疇蔓延，見 [T-10 範疇蔓延](../theory/T-10-scope-creep.md)。
    - **D 錯：** 範疇凍結不代表不能變更，而是變更要經過流程。
