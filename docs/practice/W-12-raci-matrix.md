# W-12 填一張 RACI (Building a RACI Matrix)

**挑出跨團隊交界處的工作與決策，為每一列指定一個當責者，並在啟動會議上讓大家挑錯。**

```text
 填 RACI 的五步驟

 1. 列項目：只列跨團隊的工作與關鍵決策
        │
        ▼
 2. 列角色：用角色名，不用人名
        │
        ▼
 3. 先填 A：每列只能一個
        │
        ▼
 4. 再填 R、C、I
        │
        ▼
 5. 檢查：
    ┌─ 每列一個 A？
    ├─ 每列至少一個 R？
    ├─ 某人的 A 或 R 太多？（負荷）
    └─ 某欄全是 I？（這個角色需要存在嗎）
```

=== "入門"

    **範例：新機房網路建置**

    | 項目 | PM | 網路負責人 | 資安 | 系統 | 機房 | 發起人 |
    |---|---|---|---|---|---|---|
    | 架構設計 | C | A/R | C | C | I | I |
    | 防火牆規則 | I | R | A | C | ─ | ─ |
    | 機櫃與電力 | I | C | ─ | I | A/R | ─ |
    | 割接計畫 | A | R | C | R | C | I |
    | 上線決策 | R | C | C | C | I | A |
    | 移交維運 | A | R | I | R | I | I |
    | 變更核准（中、大） | R | C | C | C | ─ | A |

    **檢查結果示例**

    - 「割接計畫」有兩個 R（網路、系統），可以，代表兩邊都要動手。
    - 「網路負責人」在 5 列是 R，負荷可能過重，需要確認是否有備援人力。
    - 「發起人」只在兩列是 A，其餘是 I 或 ─，符合發起人只管關鍵決策的角色。

    **最常見的錯誤**

    把所有工作都列進去，表格變成幾十列，沒有人會看。只列「如果沒講清楚就會出事」的項目。

=== "進階"

    **RACI 的變形**

    - **RASCI**：多一個 S（Support，支援），用在需要協助但不負主要執行責任的角色。
    - **DACI**：用於決策，D（Driver，推動者）、A（Approver，核准者）、C（Contributor）、I（Informed）。

    選哪一種不重要，重要的是團隊有共同的語言。

    **啟動會議上的使用方式**

    把 RACI 投影出來，請每個角色看自己那一欄，問：「這些是你以為的責任嗎？有沒有你覺得不該是你的？有沒有你覺得應該是你、但沒寫的？」異議越多，越早解決越好。

    **資深 PM 的檢查問題**

    - 每個 A 本人知道自己是 A 嗎？
    - 有沒有某一列的 A 其實沒有權力做那個決定？

## 小測驗

在上面的範例中，如果「防火牆規則」這一列的 A 從資安改成網路負責人，最可能帶來什麼問題？

- A. 沒有問題，網路負責人比較懂設定
- B. 合規審查的責任變得模糊，網路團隊同時負責設定與合規判斷，缺少獨立的檢查
- C. 資安團隊的工作量會增加
- D. 發起人會不高興

??? success "看答案與解析"
    **答案是 B。**

    - **A 錯：** 懂設定和對合規負責是兩回事。
    - **B 對：** 讓執行者同時當責於合規，失去了職責分離 (Segregation of Duties) 的保護，是常見的稽核缺失。
    - **C 錯：** 資安的工作量反而可能減少，但風險上升。
    - **D 錯：** 與這個改變沒有直接關係。
