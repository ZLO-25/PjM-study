# W-01 寫一份專案章程 (Writing a Project Charter)

**用一到兩頁，把「為什麼做、做到什麼算成功、範圍到哪裡、誰說了算」寫下來，並取得發起人簽核。**

```text
 一頁章程的版面

 ┌─ 1. 專案名稱、發起人、PM、日期
 ├─ 2. 為什麼要做（問題 / 機會）
 ├─ 3. 目標與成功標準（可量測）
 ├─ 4. 範圍：做什麼 / 不做什麼
 ├─ 5. 主要里程碑
 ├─ 6. 預算概算與資源
 ├─ 7. 主要風險與假設
 ├─ 8. 主要利害關係人
 ├─ 9. PM 的權限
 └─ 10. 核准簽名

 寫作順序建議：2 → 3 → 4 → 其他
 （先想清楚「為什麼」和「成功是什麼」）
```

=== "入門"

    **範本**

    | 欄位 | 填寫說明 |
    |---|---|
    | 為什麼要做 | 用業務語言寫 2–3 句，不寫技術細節 |
    | 目標 | 1–3 個，每個都要可量測 |
    | 成功標準 | 結案時怎麼判斷成功 |
    | 範圍內 | 主要交付物，條列 |
    | 範圍外 | 至少三項，避免日後爭議 |
    | 里程碑 | 3–6 個關鍵日期 |
    | 預算 | 給範圍，例如「約 X–Y 元」並註明假設 |
    | 風險與假設 | 前三大即可 |
    | PM 權限 | 例如：可核准 X 元以下的變更、可調度哪些人 |

    **範例（虛構）：分公司網路更新**

    - **為什麼要做**：分公司現有路由器已停止原廠支援，近一年發生兩次故障，每次中斷約半天，影響門市結帳。
    - **目標**：在第三季結束前完成 12 間分公司設備更新；更新後半年內，網路造成的營業中斷為零。
    - **範圍內**：路由器與交換器更換、設定移轉、測試、文件更新。
    - **範圍外**：門市 POS 系統更換、無線網路升級、分公司線路頻寬調整。
    - **PM 權限**：可在不超過總預算 5% 的範圍內調整採購項目；跨分公司的施工順序由 PM 決定。

    **最常見的錯誤**

    把章程寫成技術規格書。章程的讀者是發起人和主管，他們需要的是「為什麼、做到哪、誰負責」，技術細節放進設計文件。

=== "進階"

    **寫的過程比寫完更重要**

    - 帶著草稿和發起人一對一討論，而不是直接寄出請他簽。討論時特別確認「成功標準」和「範圍外」，這兩欄最常出現認知差異。
    - 如果發起人對某一欄說「先不用寫」，把它記為一個假設或待決事項，並約定何時確認。

    **敏捷或混合式專案的章程**

    可以把「範圍」改寫成「產品願景 + 高階目標 + 邊界」，細部範疇交給待辦清單；但「成功標準」「決策權」「預算上限」仍然要寫清楚。

    **資深 PM 的檢查問題**

    - 一個新加入的成員只讀這一頁，能說出專案要做什麼嗎？
    - 發起人有權力核准這份章程裡的預算嗎？
    - 三個月後有人提出新需求時，這份章程能幫我判斷它是否在範圍內嗎？

## 明天上班可以怎麼用

- 用上面的範本，為你目前的專案補一份一頁章程。
- 和發起人約 20 分鐘，只討論「成功標準」和「範圍外」兩欄。
- 把章程放在專案團隊都看得到的地方，並在啟動會議上逐項說明，見 [W-13 專案啟動會議](W-13-kickoff-meeting.md)。

## 小測驗

以下哪一條最適合寫在章程的「成功標準」？

- A. 「網路更穩定」
- B. 「導入新一代設備」
- C. 「更新完成後六個月內，因網路設備造成的營業中斷為零」
- D. 「使用者滿意」

??? success "看答案與解析"
    **答案是 C。**

    - **A 錯：** 沒有定義「穩定」，結案時無法判斷。
    - **B 錯：** 這是手段（交付物），不是成功標準。設備換了不代表問題解決。
    - **C 對：** 可量測、有期間、直接連到「為什麼要做」的業務問題，見 [T-04 商業論證與效益](../theory/T-04-business-case.md)。
    - **D 錯：** 方向對，但需要定義衡量方式，例如滿意度調查分數。
